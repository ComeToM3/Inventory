## 1. Verdict

Le Mode Organiser est accessible dans les trois espaces. Réordonnancement des frères, changement de parent compatible via **Déplacer vers…**, refus des destinations incompatibles, persistance de l’ordre et des relations après redémarrage : **implémentés, testés et observés** (simulation ADB).

Réserves : interaction tactile au doigt non démontrée (ADB uniquement) ; glisser-déposer frère non exercé sur l’émulateur (Monter/Descendre utilisés). Aucun P0/P1 bloquant sur les parcours essentiels.

## 4. Migration SQLite

- Schéma **v8 → v9**.
- Colonne `nodes.sibling_order INTEGER NOT NULL DEFAULT 0`.
- `_migrateToV9` : seed déterministe par groupe `(inventory, space, parent)` selon l’ordre d’affichage antérieur.
- Nouveaux nœuds : ordre en fin de fratrie.

**Implémenté. Testé** : migrations existantes + scénarios organize engine (réouverture DB).

---

## 5. Activation et sortie du mode

- Menu **⋯ → Organiser** (chaque espace).
- Bannière « Mode Organiser — glissez pour réordonner, ou Déplacer vers… ».
- FAB / actions de création masquées ou non gênantes ; bouton **Terminer** dans l’AppBar.
- Sortie : retour immédiat à l’UI normale.

**Implémenté. Observé** (ADB) : Biens, Stock, À acheter.

---

## 6. Réorganisation entre frères

- Poignées **Monter** / **Descendre** + glisser vers un frère (UI).
- Persistance immédiate via `reorderSiblings` / `placeSiblingBefore` (pas de bouton Enregistrer).

**Implémenté. Testé** : `organize_engine_test`, test M3.1 dans `inventory_engine_test`.  
**Observé** (ADB) : Biens Cuisine/Salon/Chambre → Chambre/Cuisine/Salon ; Stock Pates/Riz ; À acheter Lait/Pain.

---

## 7. Déplacement entre parents

- En mode Organiser, l’action détail devient **Déplacer vers…** (réutilise le sélecteur).
- `moveNode` place le nœud en fin de fratrie du nouveau parent.
- Destinations filtrées : pas de soi, descendant, type incompatible, autre espace.

**Implémenté. Testé** : move valide, cycle, parent incompatible, inter-espaces.  
**Observé** (ADB) : Cafe Cuisine → Salon ; sélecteur Cuisine sans Cafe comme destination.

---

## 8. Persistance

- Ordre par parent et par espace via `sibling_order`.
- Conservé après force-stop / relance.

**Observé** (ADB) : Biens Chambre→Cuisine→Salon ; Cafe sous Salon ; Stock Pates ½ puis Riz 1 ; À acheter Lait ×3 puis Pain ×1.

---

## 9. Isolation des espaces

- Réordonnancement et déplacements confinés à l’espace courant.
- Aucun déplacement Biens ↔ Stock ↔ À acheter.

**Testé** : `refuse un déplacement entre espaces`.  
**Observé** : Organiser indépendant par onglet.
