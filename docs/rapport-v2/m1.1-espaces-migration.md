## 1. Verdict

**VALIDÉ SOUS RÉSERVES.** Socle technique `space` en place, migration additive v4→v5 vérifiée sur base temporaire isolée, sauvegardes V1 interprétables (`space` → `goods`), moteur refusant les parents inter-espaces. Réserves : aucune validation manuelle sur appareil / émulateur ; pas de campagne de tests automatisés du dépôt ; CHECK SQL `space IN (...)` présent sur créations neuves, pas rétro-appliqué aux tables migrées par `ALTER` (garde domaine + backup).

Ce n’est **pas** une validation utilisateur de l’application V2, ni une autorisation d’installation.

## 4. Description exacte de la migration

Migration **additive** (pas de recreate de `nodes`) :

```sql
ALTER TABLE nodes ADD COLUMN space TEXT NOT NULL DEFAULT 'goods';
UPDATE nodes SET space = 'goods' WHERE space IS NULL OR space = '';
```

Effets :

- Tous les nœuds V1 (actifs et retirés) reçoivent `goods`.
- Identifiants, `parent_id`, noms, quantités, valorisations, statuts, dates **inchangés**.
- Contrainte quantité `>= 1` **non modifiée** (réservée à M2.1).
- Pas de `sort_index`, unités, mouvements, médias, préférences.

Création neuve (`onCreate`) : table `nodes` inclut `space` avec défaut `'goods'` et  
`CHECK (space IN ('goods', 'stock', 'to_buy'))`.

## 5. Modifications du domaine et du moteur

- Enum `InventorySpace` : `goods` / `stock` / `toBuy` (`to_buy`).
- `InventoryNode.space` obligatoire.
- `createNode(..., space: InventorySpace.goods)` par défaut.
- `_requireValidParent(..., childSpace:)` refuse un parent d’espace différent → `InventoryErrorCode.spaceMismatch`.
- `moveNode` / `_writeMove` : ne modifie **jamais** `space` ; exige parent homologue.
- Lectures préparées pour M1.2 : `getRootLocations({space})`, `getWithdrawnItems({space})`, `searchNodes` filtre `criteria.space` (défaut `goods`).

## 6. Préservation des comportements V1

- Aucun changement d’ergonomie (pas de barre inférieure, pas d’écran Stock/À acheter).
- Appels UI existants → défaut `goods` → hiérarchie Biens uniquement.
- Anti-cycle, CRUD, valorisation, totaux, retrait : chemins inchangés hors passage de `space`.
- **NON VÉRIFIÉ** sur émulateur / Moto (interdit sans autorisation).

## 11. Limitations connues

- Stock / À acheter créables au **moteur** mais **non exposés** à l’UI (volontaire).

- `spaceMismatch` non mappé dans les messages UI (parcours UI goods-only).
